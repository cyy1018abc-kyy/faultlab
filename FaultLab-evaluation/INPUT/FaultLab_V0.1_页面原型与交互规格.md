# FaultLab V0.1 详细页面原型与交互规格

> 文档类型：产品需求与低保真交互原型方案（非实现代码）  
> 版本：V0.1 / FL-001  
> 基准日期：2026-10-27  
> 设计范围：实验首页、系统交互图、实时曲线页、故障因果解释面板、实验结果对比页  
> 本轮目标：明确导航、控件、状态、数据语义、验收要求，不开展技术栈选型或代码实现。

## 0. 一页结论与设计原则

**一句话体验：** 用户无需安装 MATLAB，选择一个故障，在第 20 秒观察电池电流传感器的 +10 A 偏置如何通过反馈回路改变实际电池功率；随后能够回放、检查每一个数值的来源，并与无故障实验比较。

**五个产品原则：**
1. **先系统，后曲线。** 用户首先理解发电机、电池、母线、负载及测量与控制链。
2. **真值、观测、推断分离。** 真实电流、测量电流、SOC 真值、SOC 估计值不混用。
3. **一条全局仿真时间线。** 系统图、曲线、事件、解释和对比都使用同一仿真时刻与运行 ID。
4. **任何结论可回溯到模型与计算。** UI 不制造数值、不把传感器残差当作实际能量损失。
5. **演示优先，复杂性渐进披露。** 初学者先使用预设，高级用户才展开控制参数与物理假设。

**本版不做：** 3D 数字孪生、实时真实设备连接、多用户排行榜、任意 `.slx` 上传运行、LLM 自动诊断和远程控制。

## 1. 场景基线与明确的物理假设

| 条目 | FL-001 基准设定 | 说明 |
|---|---|---|
| 故障 | 电池电流传感器正向偏置，20.0 s 起 +10 A | 仅测量通道直接受偏置影响 |
| 仿真时长 | 0—60 s | 与播放墙钟时间无关 |
| 采样周期 | 0.1 s | 常规网格共 601 个点；事件前后状态额外记录 |
| 恒定负载 | 30 kW | 本例全部满足 |
| 直流母线 | 理想 400 V | 不展示未经建模的母线跌落 |
| 初始发电机功率 | 20 kW | 可视作理想平衡源，瞬时补偿，不代表实际机组动态 |
| 初始电池功率 / 电流 | 10 kW / 25 A | 电池放电为正 |
| 电池能量容量 | 40 kWh | 对应在恒压理想化前提下的等效 100 Ah |
| 初始 SOC | 60% | 不包含温度、OCV-SOC 非线性和效率损耗 |
| 控制模式（默认） | 测量值参与闭环反馈 | 备选：仅监测、不参与反馈 |
| 闭环行为级时间常数 | 1.5 s | 仅供解释因果机制，并非已验证设备控制器 |

**行为级模型（闭环模式）：**

- 测量：`I_meas(t) = I_true(t) + b(t)`；偏置 `b(t)=0`（`t<20 s`），`b(t)=10 A`（`t>=20 s`）。
- 反馈等效模型：`tau * dI_true/dt + I_true = I_ref - b(t)`，其中 `I_ref=25 A`、`tau=1.5 s`。
- 因而 `t>=20 s` 时：`I_true(t)=15 + 10 * exp(-(t-20)/1.5)` A；`I_meas(t)=I_true(t)+10` A。
- 仅监测模式：`I_true(t)=25 A` 恒定，`I_meas(t)` 在第 20 秒跳至 35 A 后保持。
- 功率：`P_bat,true=0.4*I_true` kW，`P_bat,meas=0.4*I_meas` kW，`P_gen,true=30-P_bat,true` kW；仅用于理想平衡。
- 真实功率守恒：`P_gen,true+P_bat,true-P_load=0`；观测一致性残差：`P_gen,true+P_bat,meas-P_load=+4 kW`（故障持续期间）。
- SOC：以真实/测量电流分别积分得到 `SOC_true` / `SOC_est`；此恒压模型下 `SOC=SOC0-∫P_bat dt/(40 kWh)`，仿真秒需换算为小时。

**关键数据校准：**

| 数值 | 无故障基准 | 闭环偏置故障 | 解释 |
|---|---:|---:|---|
| 60 s 电池电能积分 | 0.16667 kWh | 约 0.12389 kWh | 故障使真实放电电流下降 |
| 60 s 发电机电能积分 | 0.33333 kWh | 约 0.37611 kWh | 理想补偿，保证需求总计 0.5 kWh |
| 60 s 真实 SOC | 59.58333% | 约 59.69028% | 放电更少，SOC 更高 |
| 60 s SOC 估计误差（估计−真实） | 0 pp | −0.11111 pp | 10 A 偏置持续 40 s / 100 Ah |
| 故障后测量功率残差 | 0 kW | +4 kW | 错误测量导致的残差，不是额外生成的实际能量 |

所有数据均为**解析示例**，不能标作真实 Simulink 运行结果、现场数据或实测结论。

## 2. 信息架构、导航与全局结构

**建议路线（信息页面，不规定路由框架）：**

- `实验首页`：查找与选择 FL-001，了解目标与前提。
- `系统`：看能源流、测量链及控制链，配置并回放实验。
- `曲线`：同步分析真实、测量和派生信号。
- `因果`：按模型定义的因果链解释“为什么变化”。
- `对比`：故障与无故障运行的等时间轴比较、导出。

全局头部：项目标识/实验名/演示模式/模型层级/运行 ID/运行状态/帮助入口；中部为当前页面；底部保留**一条跨页共享的时间线**（桌面端固定，移动端折叠）。

```text
[FaultLab] [FL-001 电流传感器偏置] [演示模式] [模型 L0] [Run-001 已完成]
[实验首页] [系统交互图] [实时曲线] [因果解释] [结果对比]
 ┌───────────────────────────────────────────────────────────────┐
 │ 当前页面主内容                                                  │
 └───────────────────────────────────────────────────────────────┘
[↺ 重播] [⏮ 0s] [◀事件] [暂停/播放] [事件▶] [速度 1x] 时间 20.0/60.0 s
[───────────────故障标记▲─────────────────────────────────────────]
```

**导航规则：** 切换页面保留实验配置、运行 ID、选中模块、当前时刻、曲线显隐和回放进度；各页面共享 `current_time`，不会因切换而重置实验。

### 3.2 控件行为与数据来源

| 控件 | 用户操作 | 行为与导航 | 状态/限制 | 数据来源 |

## 4. 页面二：系统交互图（System Lab）

### 4.1 桌面布局与交互图

```text
┌────────────配置与实验控制──────────┬──────────模型拓扑及动态流──────────┬──────────部件检查器─────────┐
│ 故障：电流传感器偏置              │ [发电机] ─电力─┐                  │ 选中：电流传感器            │
│ 幅值：+10 A                       │                ↓                   │ 真实电流 I_true            │
│ 时刻：20.0 s                      │ [电池] ─电力─[直流母线]─[负载]     │ 测量电流 I_meas            │
│ [闭环反馈 / 仅监测]               │    │                                │ 故障偏置 b(t)             │
│ [应用并创建运行]                  │  [电流传感器]→测量→[控制器]        │ [查看对应曲线]              │
│ [重播] [暂停] [跳到20s]            │       （故障点高亮）               │ [解释异常来源]              │
└───────────────────────────────────┴────────────────────────────────────┴──────────────────────────────┘
```

不同类别的连线必须不同：**实线/方向箭头为实际功率流，虚线为信号流，故障标记专属图形**；颜色只是辅助，不承担唯一含义。

### 4.2 控件规格

| 控件 | 操作与动作 | 生效范围 | 状态约束 | 数据来源 |
|---|---|---|---|---|
| 故障幅值滑块 / 数字输入 | 更改 +10 A 为其他允许数值 | 只修改待运行草稿；当前 Run 不变 | 运行中锁定；修改使草稿 `dirty` | `scenario_config.bias_A`、`scenario_schema.bounds` |
| 故障触发时间 | 设置 20 s | 重运行后生效，绘制预定事件标记 | 必须 `0<=t_fault<duration` | `scenario_config.fault_time_s` |
| 控制模式切换 | 「闭环反馈」↔「仅监测」 | 创建对比用新 Run；不得改写原 Run | 运行中锁定 | `scenario_config.feedback_mode` |
| 「应用并创建运行」 | 校验参数→创建不可变 Run→计算轨迹 | 更新当前 Run 与所有页面 | `ready/dirty` 可用；`invalid` 禁用 | `scenario_config`、`model_engine`、`run_registry` |
| 点击发电机、电池、母线、负载、传感器或控制器 | 选中对象 | 右侧检查器与相关信号同时切换 | `selected_component` | `topology_nodes`、`signal_bindings` |
| 「查看对应曲线」 | 打开曲线页 | 自动勾选当前部件的信号 | 保留当前时间 | `signal_bindings` |
| 「解释异常来源」 | 打开因果页 | 以当前节点为焦点 | 若无故障先给预期提示 | `causal_graph`、`event_log` |
| 「跳到故障点」 | 点击 | 暂停播放并定位 20.0 s | 故障点存在时可用 | `event_log` |
| 「重播」 | 点击 | 同一 Run 从 0 s 播放，不重新计算 | 有 Run 才可用 | `run_timeseries` |

| 电池 | `I_bat_true`、`P_bat_true`、`SOC_true` | `MODEL_STATE` |

## 5. 页面三：实时曲线页（Signals & Timeline）

### 5.1 页面布局

```text
[信号分类：电流 | 功率 | SOC | 残差] [叠加基准组] [导出 CSV]
[主曲线区：真实值实线、测量值虚线、20s故障竖线、当前时刻游标]
[右侧数据快照：时刻、值、单位、来源类型、计算/事件说明]
[缩放窗口：全时段 / 故障前后±5s / 自定义]
[共享播放控件 + 跳转到 20s]
```

### 5.2 控件规格

| 控件 | 操作/行为 | 状态限制 | 数据来源 |
|---|---|---|---|
| 分类标签 | 选择电流/功率/SOC/残差 | 切换图层不影响播放和 Run | `signal_catalog` |
| 信号显隐复选框 | 单独显示/隐藏真实电流、测量电流等 | 同图至少留一个信号 | `run_timeseries`、`signal_catalog` |
| 时间游标拖拽 | 改变 `current_time`，所有页面同步 | 拖拽时暂停播放；0–60 s | `run_timeseries`、全局 `playback_state` |
| 「前/后事件」 | 跳至 20.0s；精确显示 `20−` 与 `20+` 事件快照 | 不进行跨不连续点平滑插值 | `event_snapshots` |
| 「故障附近」 | 将视图缩放至 15–25 s | 只改变图表 viewport | `chart_view_state` |
| 「基准叠加」 | 加入无故障 Run 的对应信号 | 需要同一模型/时长/配置版本 | `baseline_run`、`run_manifest` |
| 点击某数据点 | 显示数值、单位、变量标识、数据生成方式 | 就近吸附原始采样点 | `run_timeseries`、`signal_metadata` |
| 「导出 CSV」 | 导出所选运行的全量原始采样序列 | 必须已有计算完成的 Run | `run_timeseries` |
| 「恢复默认」 | 复位缩放、信号显隐，不重运行 | 所有播放状态均可使用 | `chart_view_state` |

### 5.3 曲线必须明确区别

- 电流：`I_true`（真实，实线）、`I_meas`（观测，虚线）、`I_ref`（目标，点划线）、`bias`（事件/可选辅助轴）。
- 功率：`P_gen,true`、`P_bat,true`、`P_bat,meas`、`P_load,served`，加总关系只在图例或检查器解释，不画非法的“实际多发 4kW”。
- SOC：`SOC_true`、`SOC_est`。默认纵轴真实值，不夸大 0.111 pp；允许独立差值放大并明确标注量程。
- 残差：`r_true=P_gen,true+P_bat,true-P_load` 与 `r_meas=P_gen,true+P_bat,meas-P_load`。前者理想为 0，后者故障后为 +4 kW。
- 同屏时间必须一致；若绘制连续插值，跨 20.0 s 跳变处使用阶跃绘制，不能使用平滑样条。

### 5.4 页面状态

- `no_run`：展示空态与「创建实验」入口。
- `computing`：显示数据生成状态，不提前显示最终结论。
- `ready/playing/paused`：全量数据已就绪，时间线可回放。
- `invalid_signal`：单位或长度与时钟不一致时明确报错，并阻止结果导出。

## 6. 页面四：故障因果解释面板（Causal Explorer）

### 6.1 信息结构

```text
[焦点事件：t=20.0 s，电池电流传感器偏置 +10 A]
[① 偏置注入] → [② 测量电流偏高] → [③ 控制器误认为放电偏大]
                                                ↓
[⑥ 测量功率残差] ← [⑤ 发电机补偿] ← [④ 真实电池放电下降]
[模型机制说明] [支持的曲线证据] [模型假设] [替代解释 / 局限]
[与“仅监测”运行比较] [定位到20s] [查看对应曲线]
```

**三个层次必须分开呈现：** 由故障配置直接定义的事实（注入了什么）、由模型结构规定的因果关系（什么信号能影响什么状态）、由数值结果支持的观测变化（某条曲线确实变化了）。这不是 AI 独立发现故障的证明。

### 6.2 控件规格

| 控件 | 用户动作 | 行为 | 数据来源 |
|---|---|---|---|
| 因果节点点击 | 选择传感器/控制器/电池/发电机/残差 | 高亮上游和下游节点，更新右侧说明 | `causal_graph`、`topology_bindings` |
| 「显示证据」 | 展开相关曲线引用 | 给出 `run_id + variable + time_window` 的具体证据 | `run_timeseries`、`evidence_links` |
| 「查看模型假设」 | 展开解释限制 | 展示理想400 V、理想发电机、行为级闭环等 | `model_manifest.assumptions` |
| 「仅监测 vs 闭环」 | 切换对照图 | 用两个 Run 对照：监测模式真电流不变，闭环模式真电流下降 | `paired_runs` |
| 「为什么显示+4kW」 | 单击残差 | 展开真实平衡式与测量平衡式及逐项数值 | `derived_metrics`、`run_timeseries` |
| 「查看原始数据」 | 单击证据 | 跳转曲线页、锁定同一时段和变量 | `signal_metadata` |

### 6.3 内容与文案约束

- 优先使用确定性模板：`因为[有记录的事件]发生在[作用通道]，且[模型连接规则]，所以[根据模型计算的状态]发生改变`。
- 解释必附适用前提与数据来源；无模型支撑时显示「本模型无法推导该现象」，不猜原因。
- 不把 +4 kW 观测残差当成实际电能损失。
- 演示模式可公开真值；未来盲诊断模式必须阻断与真值相关的节点、工具响应与深链 URL。

## 7. 页面五：实验结果对比页（Compare & Report）

### 7.1 页面结构

```text
[基准 Run：无故障]    VS    [试验 Run：20s +10A，闭环]

```

### 7.2 核心控件

| 控件 | 动作 | 约束 | 数据来源 |
|---|---|---|---|
| 左右 Run 选择器 | 选择基准 / 故障运行 | 校验版本、时长、单位和相同初始条件 | `run_registry`、`run_manifest` |
| 「叠加」 | 同轴比较同一信号 | 画法及单位一致 | `run_timeseries` |
| 「双屏」 | 两个窗口共用时间线 | 游标和播放速度同步 | `run_timeseries`、`playback_state` |
| 「差值」 | 展示故障组－基准组 | 仅可对比同语义、同单位信号 | `comparison_engine` |
| 指标卡 | 点击进入指标定义和积分时间范围 | 缺失数据时显示「不可用」，不填 0 | `derived_metrics`、`metric_definitions` |
| 「导出报告」 | 生成说明、图表、配置与可信度标签 | 完成计算与检查后可用 | `report_builder`、`run_manifest`、`quality_checks` |
| 「导出证据包」 | 输出数据、配置、事件、清单及哈希 | `validation_failed` 时仅允许标记为未通过，不生成“验证通过”标签 | `artifact_registry`、`quality_checks` |

### 7.3 必备指标

1. 负载需求电能和实际服务电能（本例均为 0.5 kWh）。
2. 发电机实际电能积分与电池实际电能积分：总和匹配实际供电电能。
3. `SOC_true` 末值、`SOC_est` 末值及两者差值（单位：百分**点** pp）。
4. 最大真实功率平衡残差 `max|r_true|`；最大测量一致性残差 `max|r_meas|`，不得混淆。
5. 故障激活时刻、持续时长、峰值偏置和真正生效的控制模式。
6. 附加展示从第 20 秒开始的实际电池电流变化量，而不是凭空写“诊断延迟”。V0.1 没有诊断算法，不统计检出率、误报率与诊断延迟。

**对比有效性：** 当模型哈希、求解设置、初始条件、负载曲线或观测定义不一致时，给出黄色信息警告并限制“因故障导致”的因果表述；当单位或时间基准不兼容时禁止差值图。

## 8. 全局控件与状态机

### 8.1 双状态设计：实验运行 vs 页面回放

实验计算状态：`empty -> draft_valid -> computing -> completed / failed`。配置修改产生新的 `draft_dirty`，但不可改变既有 completed Run。

回放状态：`stopped -> playing -> paused -> ended`。切换页面与选择曲线只影响显示；播放速度只改变用户观看速度，不改变物理时间步长。

| 触发操作 | Run 数据 | 仿真时间游标 | 页面行为 |
|---|---|---|---|
| 进入实验 | 新建草稿，无结果 | 0 s | 打开系统页 |
| 「创建运行」 | 生成新不可变 Run | 0 s | 计算成功后可播放 |
| 播放 | 不变 | 按速度前进 | 连动所有页面 |
| 暂停 | 不变 | 固定当前值 | 支持查看细节 |
| 时间线拖动 | 不变 | 跳转选定时刻 | 自动暂停、更新数值和图 |
| 跨页面导航 | 不变 | 不变 | 保持选中部件与曲线偏好 |
| 参数改动 | 原 Run 不变；草稿 dirty | 原 Run 游标不变 | 提示「改动须创建新运行」 |
| 重播 | 不变 | 回 0 s | 不重新计算 |
| 重置草稿 | 不变 | 不变 | 恢复默认参数，不清除历史 Run |
| 导出 | 不变 | 不变 | 以不可变 Run 和其完整原始数据为依据 |

### 8.2 异常状态设计

- **模型加载失败**：提供重试与错误信息，不用模拟曲线假装成功。
- **参数无效**：说明具体范围/单位，禁用创建运行。
- **计算失败**：记录失败环节和错误类型，保留草稿供修改。
- **数值守恒检查失败**：红色“验证未通过”，不发布“可信仿真”结论；允许导出带失败标签的排障数据。
- **对照条件不一致**：标出差异和不可比较的指标。
- **导出失败**：提示重试并保留现有 Run；不宣称已经生成文件。

## 9. 统一数据协议（产品层字段概念）

| 数据对象 | 必要字段示例 | 存在价值 |
|---|---|---|
| `experiment_catalog` | experiment_id、title、summary、supported_modes | 首页入口 |
| `scenario_config` | model_id、version、duration_s、dt_s、fault_time_s、bias_A、feedback_mode、initial_SOC | 可复现输入 |
| `model_manifest` | model_hash、assumptions、units、equation_set、limitations | 模型身份和可信度 |
| `run_manifest` | run_id、config_hash、model_hash、start/end、engine_version、status | 绑定不可变运行 |
| `run_timeseries` | time_s、I_true_A、I_meas_A、P_gen_true_kW、P_bat_true_kW、P_bat_meas_kW、P_load_demand_kW、P_load_served_kW、SOC_true_pct、SOC_est_pct | 页面唯一数值源 |
| `event_log` | event_id、event_type、trigger_s、target_signal、magnitude、phase | 故障标记与回放 |
| `event_snapshots` | event_id、t_s、phase(pre/post)、variables | 保护第20秒不连续细节 |
| `signal_metadata` | variable_id、display_name、unit、source_kind、definition、visible_in_demo | 曲线图例与证据追踪 |
| `causal_graph` | node_id、upstream/downstream、relation_type、model_rule_id | 模型机制解释 |
| `derived_metrics` | metric_id、value、unit、time_window、method、source_run_ids | 指标解释与对照 |
| `quality_checks` | check_id、status、tolerance、computed_value、message | 防止不可信结论 |

`source_kind` 建议枚举：`CONFIG`、`MODEL_STATE`、`OBSERVATION`、`CONTROLLER`、`FAULT_EVENT`、`DERIVED`、`MODEL_ASSUMPTION`。说明文本不能反向作为计算数据源。

**重要的数据保护规则：** 真实状态与公开演示观测分开存储或分开授权；演示界面能主动展示真值，不意味着未来盲评 API 也能访问。所有信号绘制以统一时间轴、相同单位系统和模型生成结果为依据。

## 10. 页面设计系统与可访问性

- 优先桌面：`≥1200px` 三栏；平板 `768–1199px` 两栏/右侧抽屉；手机窄屏按「控制—系统—数据」堆叠，时间线保留可展开缩略控件。
- 真实信号和观测信号同时用**线型+文字+颜色**区别；不要仅靠红绿区分状态。
- 主按钮可见状态：默认、hover、focus、disabled、loading；每个禁用状态有明确原因。
- 键盘：空格播放/暂停、左右箭头 ±0.1s、Shift+左右 ±1s、Home/End 跳 0/60s；前提是焦点不在输入框内。
- 图表支持表格模式，变量名和单位随读数一起暴露给屏幕阅读器。
- 支持降低动画效果；放大时间轴或纵轴时显示醒目缩放提示。
- 弹层与抽屉打开时管理焦点，关闭时还原焦点。

## 12. 建议的产品范围裁定（避免 V0.1 过度设计）

**P0：必须实现的体验**：完整五页面、FL-001 默认闭环模式、20s +10A 偏置、基础控制与真值分离、实时曲线、基准对照、确定性因果解释、CSV/配置导出、校验提示、响应式桌面体验。

**P1：有余力再完善**：仅监测模式对照、可选择幅值和故障时刻、差值曲线、完整 HTML 报告、多维数据源检查器、无障碍深度优化。

**P2：另立项目阶段**：其它故障/系统模型、Simulink/FMU 可插拔后端、盲诊断、Agent Arena、开放 Benchmarks、云端账户与分享。

建议先用一个演示证明这条完整路径：**打开首页 → 进入系统 → 在 20 秒观察传感器偏置 → 检查真实/测量曲线 → 追溯因果 → 与无故障基准对比 → 导出可复现数据。** 这是 V0.1 最明确、最可验收的产品价值。
