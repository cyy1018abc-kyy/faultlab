## 1. 物理审查（独立复核）

### 1.1 复算对象、方法、口径

复算对象为 V0.1 §1 与 V0.2 §5.2/§5.3 的 FL-001 模型：

- `b(t)=0 (t<20)`，`=10 A (t≥20)`；`I_meas=I_true+b`；`tau=1.5 s`，`I_ref=25 A`。
- 闭环：`tau·dI_true/dt + I_true = I_ref − b(t)`，`I_true(20)=25 A` ⇒ `I_true(t)=15+10e^{−(t−20)/1.5}`。
- 仅监测：`I_true≡25 A`。
- `P=0.4·I`（400 V / 1000，A→kW）；`P_gen := 30 − P_bat`；`r_true := P_gen+P_bat−P_load`；`r_meas := P_gen+P_bat,meas−P_load`。
- `SOC% = 60 − 100·(1/40)·∫P/3600 dt`（放电为正）。

计算方式：**Python 3.12 双精度**独立重写闭式解；能量用（a）符号/闭式积分，（b）0.1 s 与 0.01 s 网格上的左矩形/右矩形/梯形/中点四种求积，（c）0.01 s 子步精确指数更新 + 梯形求积三种路径交叉核对；所有数值可由复算脚本重放（见附录 A）。**没有读取或复用任何既有实现代码**。

### 1.8 物理结论清单（定义 / 恒等式 / 假设 / 推导）

**A. 定义（模型构造，不是物理发现）**

- `I_meas(t) ≡ I_true(t)+b(t)`；`b(t)` 是注入的阶跃偏置。
- `P_bat,true ≡ 0.4·I_true`；`P_bat,meas ≡ 0.4·I_meas`（400 V 等效，A→kW）。
- `P_gen,true := P_load,d − P_bat,true`（"理想瞬时平衡源"）。
- `r_true := P_gen+P_bat−P_load`；`r_meas := P_gen+P_bat,meas−P_load`。
- `SOC_true := 60 − 100·(1/40)·∫P_bat,true/3600 dt`；`SOC_est` 用 `P_bat,meas`（库仑计数）。
- `feedback_mode ∈ {closed_loop, monitor}` 决定 `b` 是否进入物理回路。

**B. 恒等式（可由定义证明；**不能**当作物理验证）**

1. `r_true(t) ≡ 0`（双精度下逐点精确 0）。
2. `r_meas(t) ≡ 0.4·b(t)`：故障期恒 +4 kW，与发电机补偿、τ、模式无关。
3. `P_gen+P_bat,true ≡ P_load,d ≡ 30 kW` ⇒ 任意线性求积下 `E_gen+E_bat ≡ 0.5 kWh`。
4. `SOC_est−SOC_true ≡ −100·0.4·b·Δt_fault/(40·3600) = −0.1111111 pp`（b=10 A、Δt=40 s），**与 τ、模式、负载无关**。
5. `I_true(20−)=I_true(20+)=25 A`（C0 连续）；`I_true` 右导数 `−6.6667 A/s`、左导数 0（C1 不连续）。
6. `E_bat,closed + E_gen,closed = E_bat,base + E_gen,base = 0.5 kWh`（能量守恒是定义式的另一写法）。

**C. 假设（L0 行为级；未验证）**

- 电池/变换器可用一阶闭环等效：`τ·dI/dt + I = I_ref − b`（等价于"控制器把**测量电流**调节到 `I_ref` 的纯积分控制；功率级为理想受控电流源"）。
- 母线恒压 400 V、无母线电容/纹波/跌落；变换器无损、无开关动态、无电流/功率限幅。
- 发电机是理想瞬时平衡源（无惯量/调频/电压/保护/机组动态）。
- 负载恒功率 30 kW，与电压/频率无关。
- 电池用理想库仑计数：无 OCV-SOC 非线性、内阻、温度、老化、充放电效率/限幅。
- 传感器仅加性阶跃偏置：无噪声、漂移动态、量化、延迟；无冗余通道。
- 电流符号约定：**放电为正**（必须在信号字典中显式声明）。
- 故障在 20.0 s 精确切换（与 0.1 s 输出网格对齐）。

**D. 推导结果（需要数值计算/可实现验证）**

- `I_true(t)=15+10e^{−(t−20)/1.5} A`；`I_true(60)=15+2.61e-11 A`。
- `E_bat,cl=446/3600=0.1238888889 kWh`；`E_gen,cl=1354/3600=0.3761111111 kWh`。
- `SOC_true,cl(60)=59.6902778%`；`SOC_est,cl(60)=59.5791667%`；`SOC_err=−0.1111111 pp`。
- 基准/仅监测：`E_bat=0.1666667 kWh`、`E_gen=0.3333333 kWh`、`SOC_true=59.5833333%`；仅监测 `SOC_est=59.4722222%`。

**E. 已"验证"的范围（诚实表述）**：仅"本报告的独立闭式复算与该文档金标准一致（内部一致性）"。**没有**模型验证、没有与实测/Simulink/FMU 对比、没有硬件验证。

| ③ 控制器误认为放电偏大 | 闭环等效：控制器调节**测量**电流到 I_ref（模型假设） | `I_ref=25 A` 恒定；`I_meas>I_ref`；无显式控制器状态 | 闭合（机制假设） |
| ④ 真实电池放电下降 | ODE 解 `I_true:25→15 A` | `I_true` [20,60] 单调下降；`P_bat,true` 10→6 kW | 闭合（推导） |
| ⑤ 发电机补偿 | `P_gen:=30−P_bat` | `P_gen` 20→24 kW | 闭合（定义+推导） |
| ⑥ 测量功率残差 +4 kW | `r_meas=0.4·b` | `r_meas` 全故障期 +4 kW | **数值闭合，但因果箭头过度**：⑥ **不依赖** ④/⑤，是代数恒等 |

**关键更正**：V0.1 §6.1 图中 `⑥ ← ⑤ ← ④` 的箭头应弱化或改画法。正确表述是：
`r_meas = (P_gen+P_bat,true−P_load) + (P_bat,meas−P_bat,true) = 0 + 0.4·b = +4 kW`。
即 ⑥ 是"测量通道误差的功率当量"，与发电机是否补偿、控制器快慢无关；它同时可作为"传感器故障在测量侧留下痕迹"的证据，但不能说"因为发电机补偿所以残差为 4"。

### 3.2 "仅监测 vs 闭环"反事实是否被正确构建

| 检查项 | 结论 | 证据/说明 |
|---|---|---|
| 同配置、唯一变量 | ✔ | 两 Run 仅 `feedback_mode` 不同；同 duration/dt/初值/负载/模型版本（须在 compare 的兼容检查中允许该字段不同，并明确标记"受控对照"） |
| 单位/时钟一致 | ✔ | A/kW/%/pp 同字典；同一 601 点时钟 |
| 反事实方向正确 | ✔ | 监测：`I_true≡25 A`、`I_meas(20+)=35 A`；闭环：`I_true→15 A`、`I_meas→25 A`。差异可归因于"测量是否进入反馈" |
| 混淆变量 | ⚠ | `P_gen` 也随模式变化（20 vs 24 kW）——是**后果**不是自变量，图上要标明"下游后果" |
| 反事实的"证据强度" | ⚠ | `r_meas=+4 kW` 在两种模式都成立（定义恒等）；`SOC_err=−0.11111 pp` 在两种模式都成立；可用作"测量误差守恒"证据，但**不能**当作"闭环导致"的证据。真正随模式变化的是 `I_true/P_gen/E_bat/SOC_true` |
| 对照是否会被 compare 误判 | ⚠ | 契约 `compareRuns` 的兼容检查若把 `feedback_mode` 差异视为"配置不一致"，会**禁止**最关键的对照图。需在规则中写："baseline↔fault 允许故障字段不同；closed↔monitor 允许 feedback_mode 不同；其余必须一致" |

### 3.3 可能被误读为"诊断算法"的表述（需加护栏）

- V0.1 §4.2 按钮"**解释异常来源**"、§6 标题"故障因果解释面板"：易被读成"系统能从数据判断原因"。→ 改为"**解释已知故障的传播路径**"，并在面板顶部常驻：**"本次故障是运行前注入的配置事实；本页不做检测/定位/诊断，无检出率与延迟指标。"**

- 契约 §11 Agent Arena 的"评分/排行榜/检出率"：这是**合成故障上的 Agent 评测游戏**，不能表述为"诊断能力验证/科学 benchmark"。→ UI 标注"扩展预览 · 合成场景 · 非真实设备诊断性能"。

| `r_meas_kW` | 列出为 DERIVED/blind，无公式 | 无法复算（功率测量全部健康，故障只在转速通道） | **✗ 定义缺失**：FL-001 的"+4 kW 残差"教学装置在 GT 没有对应量；若硬造会造假 |
| `r_true_kW` | "=0" | 瞬时 `P_gen+P_bat−P_load` 在暂态可达 **≈−0.099 kW**（t≈24.8 s；60 s 仍 −0.003 kW）；只有减去 `P_rotor`（=K_J·df/dt）后才恒 0 | **✗ 定义冲突**：须明确 `r_true := P_gen+P_bat−P_load−P_rotor`，且它是定义恒等 |
| 惯量一致性 | `P_rotor=K_J·df/dt`，K_J=5 kW·s/Hz | 本模型隐含 E_kin(f)=½·(K_J/f₀)·f²（E=125 kW·s@50 Hz）；若按 ½K_J f² 检查会差 ~50× | **✗ 未声明线性化**：必须写明"在 f≈f₀ 处线性化"，否则独立校核会得到数量级错误 |
| 电池额定 | "电池缓冲（5 kW 基准）" | sensor_drift 稳态放电 12.2 kW、load_step 瞬态 12.1 kW | **⚠ 额定/限幅矛盾**：无逆变器限幅、无能量裕度说明 |

**为什么比 FL-001 更危险**：GT 演示的是**频率**——电力系统安全相关量，且模型包含"惯量+调速器+一次调频"三个看起来像机组/电网动态的环节。但契约没有列出 GT 专属的未建模物理（AVR/电压、功率角、汽轮机/锅炉、保护、负荷频率特性、变流器限幅、多机分散），验收中仍有一处明显错误（恢复时间）、两个信号无定义（`r_meas`、`r_true` 含转子项）、一处隐含线性化未声明、一处额定矛盾。学生/评审者很容易把 49.7 Hz 稳态偏移、−0.4 Hz nadir 当成"机组动态得到验证"。**这正是 V0.2 §1.2 R-02 所禁止的"虚构的发电机滞后曲线、频率波动"的同类风险——虽然 R-02 措辞针对 FL-001，但精神适用于任何"包装成机组动态"的演示。**

### 10.4 FL-001 §5.1 扩展（load_step）判定：契约内部矛盾 + 违反 V0.2 R-02

契约 §5.1 原文（关键句）："扩展 `load_step`：……假设发电机为一阶惯性源 `tau_gen=2.0 s` 追踪 `P_load_demand − P_bat_true`；电池电流保持 `I_ref` 反馈控制"；验收又写："`P_gen_true` 约 2 s 时间常数升到 30 kW；真实电池电流从 25 短暂升到约 50 A（发电机爬坡期间），约 10 s 后回落 25 A；守恒 ≤1e-6。"

复算与矛盾：
- **解释 A（照文字：I_true 保持 25 A ⇒ P_bat=10 kW）**：负载 40 kW 下，发电机从 20 kW 以 τ=2 s 爬向 30 kW，期间 `P_gen+P_bat−P_load = 20+10−40 = −10 kW` 起，按 e^{−t/2} 衰减；**最大失衡 10 kW**，与"守恒 ≤1e-6"相差 7 个数量级。且契约未定义母线电容/储能状态，缺失的 10 kW 无处可去。
- **解释 B（照验收叙事：电池电流升到 50 A ⇒ P_bat=20 kW）**：守恒可成立，但电池电流**不再保持 I_ref**，且 25→50 A 的阶跃没有动态/限幅；这与"电池电流保持 I_ref 反馈控制"直接矛盾。
- 此外，"发电机一阶惯性源"与 V0.2 §1.2 R-02"发电机在本模型中必须是瞬时平衡补偿源，**绝不能**呈现虚构的发电机滞后曲线"直接冲突；V0.1 §4.3 也要求"不展示母线电压尖峰、发动机转速跌落或虚构的保护动作，因为 V0.1 没有对应方程"。

**结论：这是本次评审发现的最严重的契约缺陷（BUG 级），且位于 FL-001 主体系统上。** 修复二选一：
(a) 删除发电机滞后，保持理想平衡源：则 `load_step` 变成 `P_gen=40−10=30 kW` 瞬时，`r_true=0`，但演示价值低；
(b) 明确引入母线电容/储能状态 `E_bus` 与 `P_bus`，守恒式改为 `P_gen+P_bat+P_bus=P_load`，并重写能量/质量检查与验收；这是新物理，必须走独立 G2b。
无论哪种，**当前文本不得进入实现**。

### 10.5 FC-001 / GT-001 的裁定建议

1. **G0 批准范围保持 FL-001 三组 Run**（基准/闭环故障/仅监测故障）+ 五页面 + 导出；把 FC-001、GT-001、三类故障族、Agent Arena **移出 V0.1 P0**，放入 P1/P2 或独立"扩展预览"路线。

   - 惯量模型声明为 f≈f₀ 线性化，并给出 E_kin(f) 公式与独立能量校核；
   - 修正验收："nadir −0.41 Hz @21.1 s；|Δf|≤0.2 Hz @30.1 s；≤0.1 Hz @36.6 s；60 s 时 49.99 Hz；稳态需 100 s 或给出容差"；

   - GT 专属未建模物理清单（AVR/电压、功率角、汽轮机/锅炉、保护、负荷频率特性、多机分散、AC/DC 整流动态）；
