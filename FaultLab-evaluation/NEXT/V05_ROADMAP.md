# V05_ROADMAP — FaultLab 长线路线图（v0.5 → v1.0）

> **性质**：战略规划文档（Lead 起草，2026-10-31）——批准后作为后续版本的架构方向锚点；
> 具体实现仍逐版本走 CHG + 门禁。本文档**不构成任何实现授权**。

---

## 0. 项目定位（不变式）

FaultLab 是**离线可运行的行为级能源系统实验场**——亲手注入故障、观察反馈回路、每个数字可回溯到模型与来源。
以下五条为所有版本共享的**架构不变式**（不可突破）：

| # | 不变式 | 含义 |
|---|---|---|
| I-1 | **零安装、零网络、零构建** | 浏览器原生 API + Python/Node 标准库；`python -m http.server` 即运行 |
| I-2 | **数据诚实性** | `model_provenance` / `model_validation` / `hardware_verification` 三字段如实标注；每个数值可回溯 `signal_id → source_kind → formula` |
| I-3 | **证据链可复核** | golden 由外置 oracle 生成、engine 只读比对、第三方 `verify_golden` / `verify_bundle` 离线复核 |
| I-4 | **门禁纪律** | 先文档后代码（G2b/G6→G7→G8）；L0→L1 物理扩展必须走 G2b；CHG 全程留痕 |
| I-5 | **合成演示定位** | 评分/检测/定位均为教学游戏；禁「检出率/诊断准确率/工业级」措辞（copy-guard 守护） |

## 2. 长线方向（四条主线）

### 主线 A — 模型纵深（L0 → L0b → L1）

> 从解析/行为级走向数值仿真级——每个系统逐步引入非线性、热效应、效率曲线等真实物理。

| 阶段 | 版本 | 内容 | 门禁 |
|---|---|---|---|
| A-1 | v0.5.x | **GT-001 非线性惯量**：去掉 f≈f₀ 线性化 → 完整摇摆方程（方程范围不变，不需 G2b）；oracle/golden 重出 | G7 |
| A-2 | v0.6.0 | **FC-001 load_step/actuator G2b 批准后实现**：因果模板正式化、golden 扩展轮 | G2b → G7 |
| A-3 | v0.6.x | **FL-001 actuator_fault G2b**：变流器限幅 + I_bat_cap（已实现未评审）| G2b → G7 |
| A-4 | v0.7.0 | **L1 数值模型**：GT-001 非线性已铺路；FC-001 电化学（PyBaMM 或自写）；FL-001 热模型（自写 ODE）| G2b（新物理）→ G7 |
| A-5 | v0.8.0+ | **多物理场耦合**：电池热-电耦合、燃料电池水管理/气体扩散、涡轮燃烧动态 | 逐步 G2b |

**约束**：PyBaMM 依赖 scipy/numpy → 违反 I-1 零第三方依赖 → **I-1 必须先修订**（可选路径：
(a) PyBaMM 仅在 Python 后端侧使用（不经浏览器），页面仍零依赖 → 不违反 I-1；
(b) 自写 ODE 纯 stdlib → 不涉及）。

### 主线 B — 系统广度（新系统）

> 在 FL/FC/GT 三系统基础上扩展新的能源系统——每系统独立 G2b + oracle + golden。

| 阶段 | 版本 | 候选系统 | 物理特征 | 教学价值 |
|---|---|---|---|---|
| B-1 | v0.6.x | **光伏逆变器**（PV-001） | DC 系统但含 MPPT 与日照变化；无旋转惯量 | 与 FL-001 互补：直流侧 + 不可调度 |
| B-2 | v0.7.x | **风力发电**（WT-001） | AC 系统 + 机械动态 + 变桨控制 | 引入风速随机性 + 间歇电源 |
| B-3 | v0.8.x | **微电网**（MG-001） | 多源耦合（PV+WT+BESS+负荷）→ 母线频率/电压 | 综合场景：多源协调 + 孤岛检测 |
| B-4 | 远期 | **输电线路**（TL-001） | 线路阻抗 + 功角稳定 | 高压输电教学 |

**约束**：每系统 = 完整 SystemDef（拓扑/信号/故障/因果/golden）≈ M→L 工期；架构上 systems.js
已支持任意 SystemDef 注册，瓶颈在物理规格评审（G2b）与 oracle/golden。

### 主线 C — 教学场景与评测生态

> 从单点故障注入走向完整教学路径——场景编排、评测竞赛、社区共享。

| 阶段 | 版本 | 内容 |
|---|---|---|
| C-1 | v0.5.x | **评测轨对外场次**：eval-session-001 已归档 → 公开场次（多 Agent 报名 + 统一盲包 + score_hash 公示） |
| C-2 | v0.6.0 | **场景编排器**：可视化场景编辑器（拖拽故障事件 → 预览曲线 → 导出场景 JSON）；场景 = 一组 {system, fault, params, t_clear, feedback_mode} 序列 |
| C-3 | v0.6.x | **教学路径**：预设教学模块（如「传感器故障→闭环响应→仅监测对照→因果解释→评测」5 步路径），每模块绑定特定系统/故障族/对比视角 |
| C-4 | v0.7.0 | **评测排行榜（本地）**：多场次成绩聚合 + 排序表（本地文件，不做云排行榜——I-1）；参与者可导入/导出成绩单 |
| C-5 | v0.8.0 | **社区场景共享**：场景 JSON 导入/导出 + 校验（closed-world 白名单），不做云存储——用户手动分享文件 |

**约束**：评测轨开放报名须解决 reveal 管理流程（组织方角色正式化）；场景编排器是最大的新 UI 面积。

### 主线 D — 架构演进

> 在 I-1…I-5 不变式内，支撑上述三主线的架构准备。

| 阶段 | 版本 | 内容 |
|---|---|---|
| D-1 | v0.5.x | **run-g2 步数稳定化**：24 步已接近维护阈值；引入 test-suite 并行（Node worker）或分拆为 run-core/run-extended 两层 |
| D-2 | v0.6.0 | **oracle 统一接口**：fl001/fc001/gt001 oracle 已独立但接口不完全一致（RUNS/simulate_run/self_check 签名差异）→ 统一 `OracleInterface` 基类；golden schema v2（含 backend 信息） |
| D-3 | v0.6.x | **FMU ctypes doStep**：拿到参考 FMU 后 fmu_runner.py 端到端验证（D-28 关闭）；bridge.py 增 `/fmu` 端点 |
| D-4 | v0.7.0 | **性能基线扩展**：内存上限 + 帧率下限（需 perf observer API 或 CDP 内存快照）；V3-03 性能阈值集扩展 |
| D-5 | v0.8.0 | **插件架构**（如果社区需求明确）：SystemDef / ScenarioTemplate / EvalAgent 作为可注册插件（JSON + JS 回调）；插件走准入审查（等效 fmu_admission） |

## 5. 架构演进路线（依赖关系）

```text
v0.5.0（当前）
  ├─ 主线 A（模型纵深）
  │   ├─ A-1 GT 非线性（不需 G2b，方程范围不变）    ← 最短路径
  │   ├─ A-2 FC 扩展 G2b → 实现                     ← 待 G2b 批准
  │   ├─ A-3 FL actuator G2b → 实现                 ← 独立
  │   └─ A-4 L1 数值模型                            ← 需 A-1 铺路（非线性化经验）
  ├─ 主线 B（系统广度）
  │   ├─ B-1 PV-001（DC + MPPT）                   ← 独立 SystemDef
  │   └─ B-2 WT-001（AC + 机械）                   ← 依赖 B-1 的架构经验
  ├─ 主线 C（教学场景）
  │   ├─ C-1 对外场次                               ← 评测轨 MVP 已就绪
  │   ├─ C-2 场景编排器                             ← 依赖评测轨稳定
  │   └─ C-3 教学路径                               ← 依赖 C-2
  └─ 主线 D（架构演进）
      ├─ D-1 run-g2 稳定化                          ← 当前阻塞（24 步）
      ├─ D-2 oracle 统一接口                        ← 依赖 A-1（非线性 oracle 经验）
      └─ D-3 FMU doStep                             ← 依赖 FMU 样本（外部依赖）
```

**关键路径**：D-1（run-g2 稳定化）→ D-2（oracle 统一）→ A-1（非线性）→ A-4（L1）→ v1.0。
**最大不确定性**：FMU 样本（外部依赖）；PyBaMM 许可证（法律面）。
