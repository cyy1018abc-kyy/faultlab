## 0. 设计目标与边界

主线 A 的目标：把三系统从解析/行为级（L0/L0b）逐步推向数值仿真级（L1），使「同一系统、
同一故障、不同模型深度」成为可对比、可验收、可教学的一等公民。

三条设计红线（源自不变式）：

1. **I-1 内的物理扩展路径必须先裁定**——引擎内自写 ODE 完全兼容；任何第三方数值库
   （PyBaMM 等）只能走后端适配器侧（FL-19 框架），浏览器页面保持零依赖；
2. **I-2 数据诚实性随层级升级**——模型层级（L0/L0b/L1）必须进入 provenance 字段并在 UI 可见，
   用户随时知道自己在看哪一层、哪条假设；
3. **I-3 证据链不因数值化而稀释**——L1 golden 不能 bit-exact 时，容差必须是有依据的分层
   制度（§3），不是放水。

## 1. 层级分类学与门禁映射

### 1.1 层级定义（形式化）

| 层级 | 定义 | 判据 | 现有实例 |
|---|---|---|---|
| **L0** | 解析/行为级：方程可手解、输出确定、golden 由解析 oracle 复算 | 闭式解或精确一阶跟随（foStep 解析积分） | FL-001、FC-001 |
| **L0b** | 非线性行为级：方程含非线性项但结构仍是低阶 ODE，数值积分可高精度复算 | 低维状态 + 光滑 RHS + 数值解稳定 | GT-001（摇摆方程线性化） |
| **L1** | 数值仿真级：方程不可手解（高维/刚性/耦合场），需专用积分器，golden 由独立数值 oracle 生成 | 新物理状态变量（温度/浓度/压力等） | 无（A-4 落地） |

**关键澄清**：L0 与 L0b 的界线是「方程集是否含非线性项」，不是「是否用数值积分」——
GT-001 现行实现已是 Euler 子步数值积分，但其方程是线性的（df/dt = residual/K_J），
归 L0b 的原因是它是完整摇摆方程的线性化（GT001 G2b §3 已声明）。

### 1.2 层级转换的门禁判定规则

> 从 GT-001 实践提炼，作为 A 线所有阶段的第一步判定：

| 转换 | 判定 | 门禁 | 先例 |
|---|---|---|---|
| 层内近似替换（方程范围不变，去掉某近似） | 方程集仍是已批准规格 §1.3 范围内的原式 | **不需 G2b**；文档 CHG + 假设修订 + G7 全链重冻结 | A-1（RFC §2.3 裁定） |
| 层内新增故障族（方程不变，新注入/限幅路径） | 方程集不变 | **G2b-lite**（FCEXT 先例：物理自洽性 + 锚点 + 因果模板） | A-2/A-3 |
| 新增状态变量/新物理（方程集扩展） | 超出已批准 §1.3 | **完整 G2b**（双路评审 + 用户批准） | A-4 各路线 |
| 多场耦合（多个新物理场联立） | 每个新场各自超出 | **逐场 G2b**（可分批） | A-5 |

## 3. 容差分层架构（T-A / T-B / T-C）

> L1 的核心架构问题：golden 比对不能再依赖「oracle 逐算子复刻引擎」的 bit-exact。
> 把 GT-001 §8 已经隐性使用的两级（±1e-9 复刻 / ~1e-4 方法等价预案）显式化为三级制度。

| 层级 | 名称 | 适用 | 容差定法 | 证据要求 |
|---|---|---|---|---|
| **T-A** | 算子复刻 | oracle 逐算子复刻引擎更新序（同语言语义、同浮点序） | ±1e-9（逐点） | 更新序伪代码冻结（GT §8 先例）；跨实现散差超限 → 降 T-B 并登记 |
| **T-B** | 方法等价 | 同一离散方法、独立实现（引擎 JS vs oracle Python） | 方法等价容差（先例：慢极点 100 s drift 7.2e-5 Hz → 基准 ~1e-4，按最慢极点时间常数标定） | 双实现 + 已知解析极限点核对（稳态/恒等式） |
| **T-C** | 数值参考 | 不同积分器/步长（L1 异法交叉验证） | 收敛阶估计：双方各自半步长自收敛，tol = max(截断估计)·安全系数≥10 | golden 附 convergence 块（步长序列 + 外推误差） |

**落地面**：

- `tolerances.gate` 增 `tier` 字段（"T-A"/"T-B"/"T-C"）；T-C 必填 `convergence` 块；
  `verify_golden.py` 按 tier 分派判据（现实现等价 T-A 硬编码，参数化即可）；
- 该字段面与 D-2「golden schema v2」**接口对接但不重复设计**——schema v2 细节归 D 线；
  A 线只承诺：A-1/A-2/A-3 全部保持 T-A；A-4 热模型起步即 T-B（自写 ODE 跨语言不可
  bit-exact 时）或 T-A（若更新序可复刻）——**实现期由 oracle 复刻实测裁定**，预案齐备。

## 4. A-1 设计：GT-001 完整摇摆方程（v0.5.x，无 G2b，G7 全链）

### 4.1 方程勘误（设计文档首要贡献——实现前必须处理）

`L1_FEASIBILITY_RFC.md` §2.3 将非线性式写作 `2(H·S/f₀)·f·df/dt = ΔP`。该式**量纲一致但
连续性不一致**：在 f = f₀ 处退化为 `df/dt = ΔP/(2H·S) = ΔP/250`，与现行线性式
`df/dt = ΔP/K_J = ΔP/5` **差 f₀ = 50 倍**——即字面替换会让所有动态慢 50 倍。

正确形式由 G2b §3 已冻结的二次型动能直接导出：

```text
E_kin(f) = (K_J·f₀/2)·(f/f₀)²           [G2b §3 已批准]
dE_kin/dt = (K_J/f₀)·f·df/dt = P_rotor   [能量守恒]
⇒ df/dt = (P_rotor/K_J)·(f₀/f)           [完整摇摆，f=f₀ 时精确退化为现行线性式 ✓]
```

**处置**：实现 CHG 中勘误 RFC 原文；规格增补以本式为准；连续性校验（f=f₀ 处与线性式
逐点一致）加入 oracle 自检。

### 4.2 引擎与 oracle 改动面（更新序变体）

- 更新序（GT §8 冻结序）**仅一行变化**：`f += residual/K_J·dt` →
  `f += (residual/K_J)·(F0/f)·dt`（f 取更新前值，槽位不变）；其余算子（钳位、foStep、
  monitor 分支、record 语义）逐字不动 → **T-A ±1e-9 可保留**（新增一次除法一次乘法，
  双侧同序即可）；
- 稳态不动：闭环平衡由积分器驱动的 `f_gov → 50` 决定，与惯量形式无关——
  `sensor_drift` 平衡点仍为 50 − b；healthy 仍 f ≡ 50；
- 瞬态小幅移动：修正因子 f₀/f 在边界 |Δf|≈1 Hz 处 ≈ 1.02（动态快 ~2%），默认
  mag=0.3 Hz 处 ≈ 1.006——**nadir、f(60)（未收敛位）、清除过冲峰 50.213 Hz、恢复时刻
  36.1 s 全部由 oracle 重算冻结**，量级预期在现容差同数量级，但必须重冻结（不假设不动）。

### 4.3 能量校核简化（G2b §3 检查式的红利）

线性化截断残差项 `K_J·Δf²/(2f₀)` 在非线性式下**消失**（能量守恒构造性成立）：

- 检查式收紧为 `|ΔE_kin(0→t) − ∫₀ᵗ P_rotor dt| ≤ tol`，tol 由离散化残差实测分布冻结
  （前向 Euler 下 O(dt²)·每步，量级远小于现 1e-6 上界；沿用 §3 ②「跨阶跃梯形伪影属预期」
  口径）；
- `E_rotor_kWh` 指标语义统一：建议新指标 `E_kin_kWh`（二次型绝对值），旧 id 保留一个
  版本周期并在 UI 标注「线性化口径（遗留）」，随后删除——禁止两个「转子能量」并存混用
  （G2b §3 明令）。

### 4.4 双轨决策（用户裁定点 D-1）

| 选项 | 内容 | 代价 |
|---|---|---|
| **(a) 双轨保留（推荐）** | run 配置增 `inertia_model: "swing" \| "linear"`；默认 swing；linear 保留用于对比视图；golden：swing → **gt001_v2**（新 id，method_id=gt001_swing_dt0.01），linear 沿用 gt001_v1 不动 | schema/UI 增一个配置面；两条更新序分支都要 oracle 复刻（改动极小，见 §4.2） |
| (b) 单轨替换 | 引擎只留 swing；gt001_v1 归档 | 失去「线性化 vs 完整」教学对比（I-5 教学定位的核心素材）；存档场次与旧 golden 的对照便利性下降 |

**推荐 (a)**：教学价值（大幅偏频下两轨分叉的可视化）+ 证据链连续性（v1 golden 存档场次
仍可独立复核）双收益，代价仅为一个配置开关。

## 6. A-4 设计：L1 数值模型首落地（v0.7.0，G2b×N → G7）

### 6.1 双路径架构（I-1 裁定路径）

```text
路径 1「引擎内」（默认）：RHS 注册表 + 自写积分器（Euler 现有 / RK4 新增）
  systems.js SystemDef 增可选块：states[] / rhs(t, y, params) / output_map
  适用：FL 热模型、（回头看）任何单场低维 ODE；浏览器零依赖完全兼容 I-1
路径 2「后端适配器」：FL-19 框架（B-1/B-5 + createFromParts + HTTP 桥）
  适用：PyBaMM 等重模型；Python 侧第三方依赖不经浏览器页面 → I-1 路径 (a)
  前置：D-3 FMU/适配器经验、许可证核实（Q-4 守卫 2）
```

**选路判据**（实现期量化）：单步 RHS 求值成本 × 总子步数（60 s × 10 子步/s = 600 步起步）；
浏览器单步预算 ~1 ms 内走路径 1，超出走路径 2。**热模型明确走路径 1**（RHS 十余次
浮点运算）；**FC 电化学待裁定**（用户裁定点 D-4）。

### 6.2 FL-001 热模型（自写 ODE，A-4 首落地，推荐排最前）

方程草案（G2b 时冻结参数与范围——用户裁定点 D-3 定最小集/含降额两档）：

```text
新状态：T_cell（°C），T_amb = 25（常数）
C_th·dT/dt = I_bat²·R_int(T) − h·(T − T_amb)          [生热 − 牛顿冷却]
R_int(T) = R₀·(1 + α·(T − 25))                        [内阻温度系数]
（可选档）P_bat_cap(T)：T > T_throttle 后线性降额     [教学档：热失控前兆的降额表现]
耦合闭合：R_int 进入端电压/功率平衡 → 反馈回 I_bat（热-电双向耦合的最小实现）
```

- 教学价值：sensor_drift（电流传感）在热维度的第二效应——误 SOC + 内阻偏移的双重偏差；
  actuator 限幅下的热积聚。新增信号 `T_cell_true_C`（观测口径 G2b 时定：仅真值 or 加感测通道）；
- oracle：独立 Python 同法 RK4 → 容差先按 T-A 尝试（更新序若可复刻）、不通则 T-B
  （§3 预案）；golden fl001_thermal_v1（独立 id，不与 L0 golden 混装）；
- provenance：`model_provenance.level = "L1"`（§8）。

### 6.3 FC-001 电化学（路线裁定后启动，A-4 尾部或 v0.7.x）

| 路线 | 方程 | 依赖 | 工期 | 容差 |
|---|---|---|---|---|
| 自写 SPM（单粒子模型） | 固相浓度 c_s(r,t) 有限差分（~10 节点）+ Butler-Volmer 代数 Newton 解 | 零（纯 stdlib） | XL | T-B 起步 |
| PyBaMM 后端 | SPM/DFN 全模型 | pip + scipy/numpy（后端侧）；BSD-3 许可证**待核实原文**（Q-4 守卫 2） | XL+ | T-C（异法参考） |

**设计建议**：热模型先落地铺完「L1 传送带」全流程（RHS 框架、T-B 容差、L1 golden、
层级 UI），电化学在 v0.7 末以独立 G2b 裁定路线——避免两个 XL 并行。

### 6.4 跨层级对比（A 线的教学 payoff，C-3 素材）

对比页增「跨层级/跨变体对比」模式：同系统同故障同参数，两列并排（L0 vs L1 / linear vs
swing）+ 差异带（Δf(t) 或 ΔV(t) 曲线）+ 每差异区间的因果解释卡（复用现有因果模板机制，
模板按层级对扩展）。**措辞红线**：差异解释只说「模型深度导致的表达力差异」，
禁「更准确/更真实/工业级」（copy-guard 扩展词表，§10 R-6）。
